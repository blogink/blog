自建网盘聚合工具：OpenList Worker 部署流程

发表于2026-10-13|更新于2026-10-13|经验记录
|总字数:1.5k|阅读时长:4分钟|浏览量:

前不久发现 OpenList 维护团队开发了 OpenList 的 Serverless 架构移植版本，这意味着可以通过 Cloudflare Workers、EdgeOne Makers 等边缘计算平台部署，而不必自备服务器。

虽然 Cf 免费版有一定限制，但小文件传输和简单的文件浏览还是足够的。

Alist 与 OpenList

OpenList 的前身是 Alist，这是一个开源的网盘聚合项目，可以自行设置并挂载第三方存储，聚合管理的同时还可以分享和下载文件。总而言之，这是一个功能丰富的实用程序，一度成为许多 NAS 系统的预装应用；你可能在许多资源分享站也见过类似的界面。

不过，它的 API 后端没有开源，也就是说所有通过 Token 挂载到 Alist 的第三方云盘账户的安全性基本靠 Xhofe 自觉。好在很长一段时间以来作者还算“老实”，项目也是勃勃生机、万物竞发的状态。

结果去年他把这个项目卖给第三方公司并退出大部分相关项目开发社群，而且好死不死这家公司（贵州不够科技有限公司）动机和前科都不干净。不久，官方文档也加入了各种商业化链接，仓库新提交的 PR 中也有疑似收集隐私的代码片段。收购时没有事先通知，还是被开发者发现后其才回复的。之前许多知名项目如 LNMP、Hutool 等，也是遭到了类似企业的类似“待遇”。

再加上 API 授权系统是闭源的……反正 Alist 是不干净了。

好在其是以 AGPL-3.0 license 开源的，社区也是迅速分支了最后一个“未受污染”的版本。在各种分支中，OpenList 这个分支是较为知名和完善的。

近两三个月，OpenListTeam 又开发了OpenList Worker，号称“无需自备服务器即可一键部署”。自从 Serv00 更新 TOS 后，我尝试寻找其他的替代品，但大多不达预期（主要是管理第三方存储的功能）。

基于 Go 的项目在 Worker 上不能直接运行，但基于 TypeScript 有机会实现。

部署

参考 OpenList Worker 文档，为确保执行顺利，先在 GitHub 中将OpenList-Worker 仓库 fork 到自己的账户中。

之后登录 Cloudflare 控制台，依次找到构建-计算-Workers 和 Pages，点击 创建应用程序按钮，连接 GitHub 并选择 fork 的仓库，然后自定项目名称；构建命令这部分等待一下会自动读取并显示，没有则手动填写pnpm run build。

（话说大改之后的控制台看着干练了一些；Pages 在创建应用程序窗口的下方，不过被归为旧版工作流了）

随后进入项目详情页，点击设置选项卡，配置变量。这部分需根据前面的文档按具体情况编写。如果和我一样使用 Cloudflare，则按照建议可以将运行时变量和密钥中DB_FORMAT的值改为sql，DB_DRIVER的值建议改为d1。另外还需创建JWT_SECRET变量，其值自行编写（可以去网上找个生成器随机生成）。

不需要提前创建 D1 数据库，OpenList 会自动完成这一步。

注册与添加

现在访问刚才部署的实例，将会跳转到环境检测界面，若提示“环境就绪”则可继续安装。填写管理员名称和密码，以及站点名称。初始化完成后即可访问。

初次登录会提示failed get storage: storage not found; please add a storage first，点击“转到存储”或页脚的“管理”，进入后台设置，按照所需填写对应的参数。

可以整个账户挂载，也可以只挂载某个路径，这里操作可能各不相同（例如我的 WebDAV 挂载指定路径，需要直接将目标路径添加到地址中），此处按自己实际情况添加。完成后返回首页，观察添加的路径是否出现并正常访问。

用户权限部分需要在后台用户中设置，默认情况下管理员账户和guest均未配置权限，需要手动启用。

部署在 Cloudflare Worker 的实例受到 Cloudflare 对请求次数和文件大小的限制，因此大文件上传可能无法成功（个人感觉 Cloudflare 免费账户这个限制还是比较严格的，使用量大的话建议自备服务器部署 OpenList）。
