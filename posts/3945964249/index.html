在 Windows 下配置并运行 Llama.cpp

发表于2026-08-24|更新于2026-09-13|经验记录
|总字数:3.6k|阅读时长:13分钟|浏览量:

据闻最近又有一个号称普通家用硬件就能跑的模型名为 Ornith，经过考查可以理解为基于 Qwen 二次开发的模型。

有不少人称其为可达到 Claude Opus 4.8 级性能（跑分嘛，基本看看就行了），但我注意到它的部分版本可用更低配的硬件得到不错的响应速度，恰好我有些工作想使用 AI 辅助但尽可能注意隐私，遂尝试。

顺便的，Ollama 基本是 Llama.cpp 套壳并封装了一些简化命令，本次也试着使用 Llama.cpp 来运行该模型。（其实是觉得 Ollama 调度不够灵活）

（llama.cpp 可以对模型进行量化、转换等操作，但我目前暂无该需求，故本文也不会过多记录）

安装

Llama.cpp 相比于 Ollama 有更好的自定义性，但相对没有后者使用起来直观和方便。如果不想手动编译，可以访问 Llama.cpp 的 Release，获取编译好的最新版本并下载。

这里需要注意，根据自己的硬件、架构和操作系统情况选择，不要下载错了。举个例子：

文件名称（省略llama-【版本号】）适用配置
bin-win-cuda-13.3-x64NVIDIA 独立显卡且配置了 CUDA
bin-win-rocm-7.14-x64适用于 AMD GPU 加速计算
bin-win-cpu-x64纯 CPU 计算，但速度很慢
bin-ubuntu-【其他】Ubuntu Linux 下使用相应方法计算（MacOS、Android 同理）

此处我以 Windows x64 平台、NVIDIA 显卡配置 CUDA 13 的版本为例，当前最新版本为b10729，故下载 llama-b10729-bin-win-cuda-13.3-x64 。如果速度缓慢可以找 GitHub 镜像，此处不再赘述。

如果使用 NVIDIA 独立显卡，请自行搜索并安装 CUDA：CUDA Toolkit 13.3 Downloads。

下载完成后，将其解压到自己喜欢的目录（建议不要有含空格、非英文字母之类的名称），如果使用 CUDA 建议下载配套的 cudart-llama-bin-win-cuda-13.3-x64（同样以 Windows 为例），然后解压到相同目录（几个 DLL 与 llama.exe 等处于相同目录下）。

现在可以直接通过命令调用，但需要输入程序完整路径；为方便调用，我们需要为其添加变量。编辑系统变量（可以用 Win+R 运行sysdm.cpl打开，也可以用 Win+S 搜索），在“系统属性”窗口中依次点击系统属性-环境变量-系统变量-选择【Path】-编辑-新建，填入刚才解压的目录（该路径下有llama.exe等文件）。

下载模型

这里我们用 Hugging Face 上的 Ornith-1.5-9B-uncensored-GGUF 模型为例（网络条件或镜像需自行解决，例如使用 Watt Toolkit、Steamcommunity302 等）。下载完成后放在 llama.cpp 的目录下，或者找一个其他的合适的目录存放（记住路径就行）。

其他的模型也可以，但建议用 GGUF 格式，在 llama.cpp 中体验比较好。考虑到性能问题，我选择了Ornith-1.5-9B-uncensored.Q4_K_M.gguf这个量化版本。

（其实把 Ollama 下载的模型的后缀名称改为.gguf也能用。）

在 llama.cpp/tools/server/README.md 中可以找到大部分启动参数，这里整理几个常用的参数：

参数名称作用附记
-m <path>/--model <path>模型路径无默认值，必须指定
-mm <path>/--mmproj <path>多模态投影文件的路径可省略
-c <N>/--ctx-size <N>上下文长度默认为 0，但也会尝试从模型中读取默认值；粗略估计为 1k≈0.1GB 显存
--keep <N>从初始提示中保留的标记数默认为 0，设置为 -1 则全部保留
-n <N>/--predict <N>/--n-predict <N>单次回答最大生成 token（部分模型的思考也会纳入统计）默认为 -1，即无限生成，直到上限
-p <text>/--prompt <text>提示词要么填写提示词，要么省略该参数（可进入交互模式）
-ngl <N>/--gpu-layers <N>/--n-gpu-layers <N>最大可存储在显存中的层数，在显存允许的范围内越大越好省略或设置为 0 则使用 CPU，设置为 -1 或 auto 则由程序决定，提示类似于 Out of memory 则减小数值
-fa <on、off、auto>/--flash-attn <on、off、auto>是否使用 Flash Attention该方法可以节省显存并提高执行效率，但部分模型可能不支持
-ctk <type>/--cache-type-k <type>K（Key）的 KV 缓存数据类型，可以进一步节省显存，允许的值有 f32/f16/bf16/q8_0/q4_0/q4_1/iq4_nl/q5_0/q5_1默认为f16
-ctv <type>/--cache-type-v <type>V（Value）的 KV 缓存数据类型用法同上，建议保持一致

下面几个变量由系统保留，一般不能修改：

  • LLAMA_ARG_MODEL
  • LLAMA_ARG_HTTP_THREADS
  • LLAMA_ARG_N_GPU_LAYERS
  • LLAMA_ARG_EMBEDDINGS
  • LLAMA_ARG_HOST
  • LLAMA_ARG_PORT
  • LLAMA_ARG_NO_MMAP
  • LLAMA_ARG_CTX_SIZE
  • LLAMA_ARG_N_PARALLEL
  • LLAMA_ARG_ENDPOINT_METRICS

如果不想玩了可输入/exit或按Ctrl+C退出。

有些如 MoE 架构的模型虽然参数量很大，但每次推理时只激活一部分参数；llama.cpp 的部分参数可以只加载一部分模型，从而使得较低配置的设备也能运行可观参数的模型，并获得基本的体验（但提升终究还是有上限的）。

对于托管在 Hugging Face 平台的模型，llama.cpp 提供了相应的参数以便直接调用；此处考虑到网络问题，将其下载至本地后再调用。

多模态能力

部分模型提供了多模态能力，但可能需要外挂相应的文件（此类名称中通常包含mmproj字样）来实现；一般情况下，这些是配套的，不建议混用。

下载这类模型后，通过-mm <path>或--mmproj <path>引入，即可为模型提供多模态能力。此时建议再加一个参数--image-min-tokens 1024，确保其在接收到图片后有一定的预算进行视觉定位和分析。

顺带一提：图片被编码后产生的大量 Token 也会被纳入单次对话 Token 设置上限。为避免模型或 llama.cpp 默认的预算不足，记得手动加参数给它调高一点。也可以给输入的图片压缩一下，减少 Token 消耗。

用配置文件预设多个模型

我的设备的显存资源比较有限，且我很少同时运行超过一个模型。我需要使用一个语言模型和识图模型，但按照前面的方式加载，我需要频繁停止和启动新进程，非常麻烦。

阅读文档可知，llama-server 提供了 Router 路由模式和相应的参数：

参数名称作用
--models-dir <PATH>包含路由服务器模型的目录（默认：禁用）环境：LLAMA_ARG_MODELS_DIR
--models-preset <PATH>指向包含路由器服务器模型预设的 INI 文件的路径（默认：禁用）环境：LLAMA_ARG_MODELS_PRESET
--models-max <N>对于路由服务器，最大同时加载模型数量（默认：4；0 = 无限）环境：LLAMA_ARG_MODELS_MAX
--models-autoload/--no-models-autoload对于路由服务器，是否会自动加载模型（默认：启用）环境：LLAMA_ARG_MODELS_AUTOLOAD

Lorem Ipsum，也称乱数假文或者哑元文本， 是印刷及排版领域所常用的虚拟文字。由于曾经一台匿名的打印机刻意打乱了一盒印刷字体从而造出一本字体样品书，Lorem Ipsum从西元15世纪起就被作为此领域的标准文本使用。它不仅延续了五个世纪，还通过了电子排版的挑战，其雏形却依然保存至今。在1960年代，”Leatraset”公司发布了印刷着Lorem Ipsum段落的纸张，从而广泛普及了它的使用。最近，计算机桌面出版软件”Aldus PageMaker”也通过同样的方式使Lorem Ipsum落入大众的视野。
